# CMH 工作流程（逐步说明）

每一步写明产出什么、谁来做、进入下一步之前要过的检查点。**人**＝研究者或标注者，**模型**＝语言模型，
**代码**＝本 skill 的脚本或你自己的代码。

请按顺序做。借助模型做语料研究时，大多数失误都出在顺序颠倒：先让模型跑起来，事后再补定义、补人的基线、补规则。

## 第 0 步　界定研究对象和结论（人）

写下：

- **分析单位**（结论表的一行）：一个概念、一个词形、一篇文档、一位发言人；
- **每条实例要判的属性**（词义、类别、立场、框架）；
- **结论类型**：逐条判定怎样汇总成结论（最早一例、各组占比、有无、比较、进统计模型的编码变量），见 `scenarios.zh-CN.md`；
- 每个来源的**观察窗**，以及落在窗口边缘的值意味着什么。

产出：`templates/protocol.zh-CN.md` 的第 1–4 节。
检查点：研究者确认。研究对象含糊，后面任何一步都补救不了。

## 第 1 步　登记语料层和证据层级（人、代码）

对每个来源写明它能支撑什么：

- 带时间的全文 → 实例级的数值（年份、占比）；
- 只返回命中数的检索接口 → 上界或曲线形状，单独不能给出数值；
- 频率序列 → 趋势，不给数值；
- 权威记录（官方名单、带日期的词典条目）→ 按它自己的层级给出数值。

层级从强到弱排序，低层级不能覆盖高层级。写下已知缺口（没有任何来源覆盖的年代或语域），它们会成为报告里的局限。

用一两天做可行性试探：在遵守来源使用条款的前提下，能不能从每一层为少数几个单元取到带时间的实例？

产出：协议第 3 节；证据层级的说明见 `evidence.zh-CN.md`。

## 第 2 步　由语料提名候选（代码；模型只当筛子）

- 扫描语料（某一时期的全部词形、符合某个框架的全部文档），或者完整使用一份可穷举的封闭名单。扫描规则和过滤条件要在看结果之前定好。
- 模型可以给候选**分类**（是不是真正的单元？属于哪一类？）。它只是筛子：它的每一条输出，包括被筛掉的，都连同调用记录一起留存。
- 只有语料提名不到的候选（例如在被扫描语料里没有先例的词形），才让模型**枚举**。它提出的每一条，都要像其他候选一样到语料里找到实例。
- 每个单元一个固定编号，编号永不复用、永不重排。

记录候选漏斗：每一环节有多少候选。数字从调用记录里数，而不是从碰巧留下来的结果文件里数。

## 第 3 步　写定义，由人审定（模型起草，人审定）

后面每一条判读都依赖定义（或编码手册的条目）。可以让模型起草；研究者逐条阅读、审定，并在定义表里把
`status` 设为 `approved`。`cmh_judge.py` 拒绝使用未审定的定义。

定义的数量远少于实例。人的时间花在这里，回报最高。

## 第 4 步　先测人（人、代码）

在选择或采信任何模型配置之前：

1. 按要紧的类别分层抽取试标样本（语言 × 正类／负类，或编码手册的类别），类别比例尽量接近正式运行时的情况。
2. 生成盲判卷（`cmh_sheet.py make`），两名及以上标注者各自独立判。
3. **按类别**计算一致度（`cmh_agreement.py`：κ、AC1、正类与负类特异一致率）。
4. 人判不一致的类别：改定义，或者不交给模型判。不要用“让模型来定”来解决人与人的分歧。
5. 在同一份卷子上跑候选的模型配置（它们只是多出来的评分列），按语言、按类别对照人的数字选择判读层。

产出：后面所有数字都要对照着读的人类基线。细节见 `human-annotation.zh-CN.md`。

## 第 5 步　冻结协议（人、代码）

把协议其余部分填完：检索规则、判读层配置、汇总与弃权规则、分流规则、审计配置、抽查数量与随机种子、
对照条件与基线、指标，以及写明每种可能结果代表什么的**解读规则**。

用 `cmh_protocol.py freeze` 冻结全部协议文件，并在第一次评估运行之前提交锁文件。提交时间就是“规则先于结果”的证据。之后加的分析按探索性报告。

## 第 6 步　分层核验（代码、模型）

1. **检索**：由代码按单元、按时期取实例，设上限，带上下文，去重。
2. **判读层**（`cmh_judge.py run --layer judge`）：每条实例调用一次，温度 0，每次调用都追加写入台账。这一层用便宜的本地模型往往就够；够不够由实测错误率决定，不由价格决定。
3. **汇总与弃权**（`cmh_aggregate.py`）：结论指向它的证据实例。没有支持实例就不下结论。落在窗口边缘的值标为删失。
4. **按写明的规则分流**（`cmh_triage.py`）：极短或歧义大的词形、窗口边缘的值、孤立的早期命中、只有一条支持实例、来源互相矛盾。对未标记的结论做带种子的随机抽查。模型的置信度绝不能把结论排除在抽查之外。
5. **审计层**（`cmh_judge.py run --layer audit`）：配置不同的模型重读每个被标记、被抽查结论的证据。被否决的证据按协议处理：删去后重新汇总，或交给人。

## 第 7 步　人测量每一层，并裁定定义问题（人、代码）

1. 把**每个**条件（只有判读层、判读层＋审计、各个基线）产出的证据实例收集起来，去重、隐去来源、打乱顺序，交给两三位没有参与搭建流水线的读者（`cmh_sheet.py make`）。
2. 核对交回的卷子（`cmh_sheet.py check`），揭盲（`cmh_sheet.py merge`），取多数决。
3. 测量（`cmh_evaluate.py`）：分流有没有把错误集中起来（`triage`）；审计捉到了什么、又弄错了什么（`audit`）；不同条件之间相比如何（`compare`）。
4. 测量**漏报**：从弃权和判否的池子里随机抽样交人判（`cmh_evaluate.py recall`）。没有这一步，“没找到”就不能写成“不存在”。
5. 对比例类结论，用人工判过的随机样本校正模型给出的估计（`cmh_evaluate.py estimate`）。
6. 取决于“什么算研究对象”的分歧交给研究者裁定，并记录裁定。这些裁定界定了研究对象，不是噪声。

## 第 8 步　单一结论表、核对、仪表、报告（代码、人）

- 所有判定都汇入同一张结论表，报告里的每个数字都由它算出。
- 把证据规则写成核对项（`cmh_check.py run`），每次重建结论表都跑一遍。每次重建都和上一个确认过的版本比对（`cmh_check.py diff`），这样没人有意改动的变化也能被看到。
- 结论表一变，就重算仪表（`evidence.zh-CN.md` 的“仪表”一节）。
- 消融：每次去掉一层，重建，报告结论变了什么。
- 每个结论都附上证据层级和该层级实测的错误率。稿子里的每个数字都对照结果文件核对（`cmh_numbers.py check`），然后再读一遍这些数字所在的句子：数字对得上，不等于句子是对的。
