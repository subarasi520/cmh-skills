# 证据：层级、观察窗、弃权、结论表、仪表

## 证据层级

每个结论都带着它所依据证据的层级。层级名称按你的研究来定；下面是一个常见的阶梯，从强到弱：

| 层级 | 是什么 | 能支撑什么 |
|---|---|---|
| `human_verified` | 人按协议读过这条实例 | 数值 |
| `authoritative_record` | 官方名单、带日期的词典条目、档案记录 | 数值，按它自己的层级 |
| `model_judged_audited` | 判读层的标签经审计层确认 | 数值，附该层级的实测错误率 |
| `model_judged` | 只有判读层的标签 | 数值，附该层级的实测错误率 |
| `rule_matched` | 字符串或模式匹配，没有阅读 | 基线；通常不能给数值 |
| `search_count_bound` | 检索接口返回的命中数 | 只能给上界或曲线形状 |
| `trend_only` | 频率序列 | 只看趋势，不给数值 |

规则：

1. 数值来自实际存在的实例。从不问模型某件事是什么时候发生的。
2. 低层级不能覆盖高层级。
3. 每个层级的错误率都要实测（工作流程第 7 步），并写在依据该层级的结论旁边。
4. 报告要写明每个层级上各有多少结论。如果大部分结论落在低层级，应在第一段说明，而不是放进脚注。

## 观察窗与删失

每个来源都有起止时间。如果最早的实例正好落在窗口起点，真实的首次使用可能更早：应作为界限报告
（`censored = left`，`value_kind = upper_bound`）。不要把删失值混进年代或时滞的分布和平均数里，否则会造出只是算术结果的“趋势”。

各来源覆盖的时期不同时（例如报纸从某一年开始、网络存档从更晚的年份开始），观察窗按来源分别计算。在不同观察窗里测量的单元之间作比较，报告里要有一句说明。

## 弃权

证据不足以支撑结论时，流水线就不下结论：没有正例、支持实例太少、来源互相矛盾、锚点被否决又没有替代。
弃权本身是结果，要报告有多少单元没有结论、为什么。一个总能给出答案的基线（字符串匹配永远能找到“第一次”出现）看起来更完整，其实更不准。

## 单一结论表

- 所有判定——模型标签、审计判定、人的裁定、权威记录——都汇入同一张表。报告里的每个数字都由它算出，不从中间文件里直接读数。
- 人工输入（裁定、人工核过的锚点）放在一个文件里，只有一个入口。重建脚本不能用别处的数据覆盖它们。
- 证据规则写成核对项（`templates/table_checks.toml`），每次重建都跑。
- 每次重建都和上一个确认过的版本比对（`cmh_check.py diff --fail-on-change`）。依赖某个标签的护栏，可能因为前一步改了标签名而失效；比对能让结果的变化暴露出来，即使原因出在别处。

## 来源追溯

每一次模型调用都要保存：层、模型名、参数、提示词模板和实际提示词的哈希、协议锁、原始输出和解析出的标签
（`cmh_judge.py` 会自动记录）。粗筛的输出也要保存，包括被筛掉的。漏斗数字要从这些记录里数，而不是从碰巧留下来的结果文件里数。

## 仪表

结论表一变就重算的只读视图。它们定义在同类流水线都会产生的中间产物上，所以可以用到别的研究里。

| 仪表 | 显示什么 | 由什么算出 |
|---|---|---|
| 候选漏斗 | 从扫描到最终结论表，每一环节的候选数 | 扫描结果、粗筛台账、结论表 |
| 独占贡献 | 每个来源或提名途径贡献了哪些别的途径没有的东西 | 带来源列的结论表 |
| 证据保真 | 实例文本里是否真的含有被检索的词形（查出模糊检索的“幻影命中”） | 实例、检索样本 |
| 删失护栏 | 有多少值落在窗口边缘，它们会改变多少结论 | 结论表 |
| 人与判读层的一致度 | 按语言、按类别 | 盲判卷＋判读层标签（`cmh_agreement.py`） |
| 标注者一致度 | 按语言、按类别 | 盲判卷（`cmh_agreement.py`） |
| 成本与规模 | 每层每个模型的调用次数、判过的实例数、人读过的条目数 | 台账（`cmh_judge.py summary`）、卷子 |
| 问题档案 | 每个已知问题、它对数字的影响、处理状态 | 和结论表放在一起的一个普通文件 |
