# CMH：语料—模型—人 核验（中文对照版）

> 智能体读取的是同目录下的 `SKILL.md`；本文件是它的中文对照版，内容一一对应。

## 概述

**不相信模型，但要通过设计让它做出可靠的工作。** CMH 把核验分给三方：

- **语料**：决定考察什么，每个结论都要落在一条实际存在的实例上。
- **模型**：分层判读实例。判读层判全部实例；按事先写明的规则标出的结论，再加一份随机样本，交给配置不同的审计层复查。
- **人**：界定研究对象、审定定义、提供盲判标签来测量每一层，并裁定边界情况。

每个结果都带着证据层级和该层级实测的错误率。证据不够，就不下结论。

## 什么时候用

- 结论要靠逐条阅读语料实例得出：判词义、类别、立场、框架。
- 大部分阅读交给模型，而受过训练的人可以按同一份书面定义来判。
- 能抽取盲判用的人工样本。

**不适用于**：不需要逐条阅读实例的频率、搭配、词向量统计；受过训练的人也判不一致的任务（先改定义）；
任何语料都证实不了的事实；针对具体个人的决定；无权合法处理的材料。详见 `references/scenarios.zh-CN.md`。

## 分工

| 角色 | 做什么 | 绝不做什么 |
|---|---|---|
| 语料（经由代码） | 提名候选；提供带时间的实例 | — |
| 判读层模型 | 按审定过的定义判每一条检索到的实例 | 凭记忆给年代、出处或例句 |
| 审计层模型（配置不同） | 复查被标记和被抽查的结论 | 不经测量就被采信 |
| 人 | 界定对象；审定定义；盲判；裁决；签字确认 | 被模型取代、不再当标尺 |
| 代码 | 检索、汇总、分流、抽样、统计、核对 | 手算数字 |

## 工作流程

详见 `references/workflow.zh-CN.md`。按顺序做。**每到一个检查点，先停下来，等研究者确认再往下走。**

| 步骤 | 做什么 | 检查点 |
|---|---|---|
| 0 | 定分析单位、要判的属性、结论类型、观察窗 | 研究者确认 |
| 1 | 登记语料层，写明每层能支撑什么（证据层级）；小规模可行性试探 | — |
| 2 | 由语料提名候选；模型只做分类（语料提名不到的才让模型枚举） | 粗筛输出全部留存 |
| 3 | 模型起草定义，研究者逐条审定 | 定义已审定 |
| 4 | 先测人：按语言 × 类别分层做盲判试标；据此选判读层 | 人在模型要判的类别上能达成一致 |
| 5 | 冻结协议，包括解读规则 | 评估运行之前提交锁文件 |
| 6 | 判读 → 汇总（证据不足就弃权）→ 按写明的规则分流＋随机抽查 → 审计 | — |
| 7 | 盲判读者判各条件的产出；测量每一层和漏报；研究者裁定边界 | 裁决有记录 |
| 8 | 单一结论表、规则核对、版本比对、仪表、消融；每个数字都核对 | 全部核对通过 |

## 铁律

1. 数值只来自检索到的实例。不让模型回答“什么时候出现的”，也不让它提供出处或例句。
2. 模型的输出是贴在某条实例上的标签，不是关于世界的事实。
3. 先测人，再测模型。模型的每个数字都要和同一语言、同一类别上人的数字对照着读。
4. 定义或编码手册的每一条，都要先经人审定，模型才能用。
5. 评估运行之前冻结协议。之后加的分析一律标为探索性。
6. 按写明的规则分流，不按模型的置信度；未标记的结论一定要随机抽查。
7. 用配置不同的模型做审计，并且既测它捉到的错，也测它误推翻的对。
8. 证据不足就弃权。只有测过漏报率，“没观察到”才能写成“不存在”。
9. 只有一张结论表。报告里的每个数字都由它算出，并对照它核对。
10. 模型的每一次输出都留存，包括被否决的和无法解读的回答。

## 智能体自己的分工

- 你负责搭建和运行流水线，但不替人完成人的步骤。需要人做的步骤（确认、审定定义、填写盲判卷、裁定），
  把材料准备好，说清楚需要对方做什么，然后停下。
- 绝不填写盲判卷，绝不让标注者看到答案键或模型标签，绝不修改交回的卷子。你自己的判断可以作为又一个评分列，但不能当标尺。
- 用平实的话报告结果，附上层级、错误率和区间：测了什么、在什么上测的、什么没测。

## 危险信号：停下来改

| 念头 | 实际情况 |
|---|---|
| “模型很强，人工试标可以省了。” | 没有人与人的一致度，模型的一致度就没有参照。 |
| “置信度很高，不用查。” | 模型标不出它自己有把握的错误。 |
| “定义是模型写的，看着没问题。” | 定义错了，后面每一条判读都跟着错。必须由人审定。 |
| “先看一眼结果，再写协议。” | 那样的分析只能算探索性。先冻结。 |
| “审计用的是更强的模型，它推翻的肯定对。” | 用人的真值去测它的误推翻。 |
| “覆盖率百分之百，测试全绿。” | 数据串行照样能过测试。跑外键、行数和版本比对检查，再亲手读一部分样本。 |
| “不显著，说明两者相当。” | 不显著只说明数据分不出两者。 |
| “报告里这个数我手算一下。” | 数字由脚本产出，并用 `cmh_numbers.py` 核对。 |
| “先找一个标注者就够了。” | 一个标注者给不出人与人的基线。 |
| “模型知道这个词是什么时候出现的。” | 模型的记忆不是证据。 |

## 脚本

只用 Python 标准库，需要 3.11 及以上。各脚本的选项用 `python scripts/<名称>.py --help` 查看。

| 脚本 | 用途 |
|---|---|
| `cmh_protocol.py` | 冻结／核对协议文件（哈希锁） |
| `cmh_judge.py` | 运行判读层或审计层模型，写只追加的台账；`dry-run` 预览提示词；`summary` 汇总台账 |
| `cmh_aggregate.py` | 实例标签 → 结论：`earliest`（定年）、`proportion`（比例）、`presence`（有无），带弃权和删失标记 |
| `cmh_triage.py` | 按写明的规则标记，并做带种子的随机抽查 |
| `cmh_sheet.py` | 盲判卷：`make`（答案键另存）、`check`（核对交回的卷）、`merge`（揭盲合并） |
| `cmh_agreement.py` | κ、AC1、正类／负类特异一致率、Fleiss κ、聚类自助法区间 |
| `cmh_evaluate.py` | `triage`、`audit`、`compare`、`estimate`（比例校正）、`recall`（漏报） |
| `cmh_check.py` | 按规则核对结论表；`diff` 与上一个确认过的版本比对 |
| `cmh_numbers.py` | 稿子里的每个数字都对回结果文件 |

模板（协议、提示词、配置、规则、标注说明）在 `templates/`。仓库的 `examples/toy/run_example.py`
用合成数据离线跑通全流程。
